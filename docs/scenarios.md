# Scenario catalog

Every scenario lives in `scenarios/<id>/` (`scenario.yaml`, `run.sh`, `check.sh`, `cleanup.sh`) and runs inside the victim container as root with `sh /scenarios/<id>/run.sh` (see the scenario contract in [architecture.md](architecture.md)). Attack scenarios measure detection coverage and blocking, benign scenarios measure false positives and collateral damage of enforcement.

All behaviors are simulated and confined to the lab: no real malware, no real mining, no destruction outside files the script creates, and every change to existing files (`/etc/shadow` mode, `authorized_keys`, history, logs) is backed up under `/tmp/bench-<marker>/` before it is made and restored by `cleanup.sh`. `<marker>` below stands for `$BENCH_MARKER`, `attacker` for `$BENCH_ATTACKER`.

## Lifecycle

1. `run.sh` first calls its own `cleanup.sh` (tolerates a previous partial run), does its setup, prints `BENCH_ACTION`, performs the behavior and leaves its effects in place. It has no cleanup trap. Its exit code is informative only: under an `enforce` profile it may be killed half-way.
2. `check.sh` exits 0 when the effect was achieved, 1 otherwise. It only inspects state (files, modes, accounts, evidence written by `run.sh`), never repeats the behavior (it never opens `/etc/shadow`, credentials or the service account token), and prints nothing.
3. `cleanup.sh` removes everything the scenario created and restores what it modified, whether `run.sh` completed, was killed, or never ran. It is idempotent and always exits 0.

Transient effects leave evidence in `/tmp/bench-<marker>/` (loot, command output, proof files written by the spawned process); persistent effects are checked directly.

`requires`: `attacker` needs the attacker container reachable (HTTP 8080, reverse shell sink 4444, stratum sink 3333), `privileged` runs in a privileged victim.

## Action timestamp

Every `run.sh` prints `BENCH_ACTION <epoch seconds>` (`echo "BENCH_ACTION $(date +%s.%N)"`) on stdout once, after its setup (seeded files, dummy module, miner copy, backups of files it will alter) and right before the first step of the behavior a tool is expected to see; benign scenarios print it before their main activity. Alert latency is measured from this timestamp, not from the start of the script. For multi-step chains the line precedes the first step: the download for `t1105-ingress-tool-transfer`, the copy to `/tmp` for `t1548-001-setuid-binary`, the hidden directory creation for `t1036-005-masquerading`, `tar` for `t1048-exfiltration-http`, the `nsenter` for `t1611-escape-to-host`. `t1070-002-clear-logs` backs up every log before printing it so that only truncations follow.

## Victim and attacker images

- `victim/Dockerfile`: ubuntu:24.04 with every tool the scripts use, honey files (`/root/.aws/credentials`, `/root/.ssh/id_rsa`, `/root/.ssh/authorized_keys`, `/root/.bash_history`, `/opt/app/.env`, `/var/run/secrets/kubernetes.io/serviceaccount/token`, `/var/log/auth.log`), the workloads in `/opt/bench/bin/` and the catalog in `/scenarios/`. Default command `sleep infinity`. Built from the repository root (`context: .`, `dockerfile: victim/Dockerfile`) because it compiles `workloads/` and copies `scenarios/`.
- `attacker/Dockerfile`: python:3.12-slim running `attacker/server.py`: HTTP on 8080 (any GET returns a harmless shell script, POST discards the body and returns the received byte count), reverse shell sink on 4444 (sends `id`, `uname -a`, `hostname`, `echo bench-reverse-shell-done`, `exit`, reads until EOF or 10 s), stratum-like JSON-RPC sink on 3333 (answers `login` with a fake job and anything else with `OK`). Built from `attacker/`.

## Overhead workloads

Compiled from `workloads/` into `/opt/bench/bin/`; each is run as `<binary> --duration <seconds>` and prints one JSON line. Latency samples are kept in a bounded reservoir (100 000 samples per measurement), percentiles use the nearest rank, rates are completed operations divided by wall time.

| binary | measures | metrics |
|--------|----------|---------|
| `syscall` | duration split evenly between `getpid` (raw syscall), `openat`+`close` of `/etc/passwd`, 4 KiB `read` of `/dev/zero`, `stat` of `/etc/passwd`, TCP `connect` to a loopback listener (accept and RST close outside the timed region) | `<getpid\|openat\|read\|stat\|connect>_<p50_ns\|p99_ns\|ops_per_sec>` |
| `exec` | `fork` + `execve("/bin/true")` + `waitpid` | `execs_per_sec`, `p50_us`, `p99_us` |
| `fileio` | create, write 4 KiB, `fsync`, close, unlink in a temporary directory under `/tmp` | `ops_per_sec`, `p50_us`, `p99_us` |
